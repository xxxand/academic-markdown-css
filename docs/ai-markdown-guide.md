# 给 AI 的 Markdown 写作指南

## 标点

- 中文内容使用全角标点：，。：；、？！“”《》。省略号写“……”，破折号写“——”。
- 英文句子、代码、网址和路径里使用半角标点。
- 括号按内容选择：中文说明用全角（），括号里是英文、文件名、代码或数字时可用半角 ()，并与前后的中文各留一个空格，例如“这是源代码 (example.py) 的说明”。

## 空格

- 中文与英文、数字之间留一个空格：“使用 Python 3 编写”“共 3 个文件”。行内代码也一样：“调用 `run()` 函数”。
- 序号与文本之间留一个空格：“第 2 步”“步骤 3：安装”“表 1 列出了结果”。
- 数字与 `%`、`°` 之间不留空格：“68%”“25°C”。
- 全角标点与相邻文字之间不留空格：“你好，World”，不要写成“你好， World”。
- 加粗和斜体的标记紧贴文字，内侧不留空格：`**重点（说明）**`。
- 段首不要缩进，也不要用全角空格。

## 数学公式 (KaTeX)

凡是能用公式表达的内容都写成公式，不要放进行内代码，也不要用 Unicode 符号拼凑。例如写 `$g(\bar{s}, a)$` 和 `$\Sigma H^T (H \Sigma H^T + Q)^{-1}$`，而不是 `` `g(s̄, a)` `` 和 `` `Σ H^T (HΣH^T+Q)^{-1}` ``。行内代码只用于变量名、函数名、命令和文件名这类程序里的文本。

行内公式写 `$...$`，独立公式写 `$$` 并各占一行，前后空一行：

```markdown
$$
f(x) = \begin{cases} 1 & x > 0 \\ 0 & \text{其他情况} \end{cases}
$$
```

公式里的中文放进 `\text{}`。公式与前后的文字、标点之间是否留空格都可以，`设 $a$ 为常数` 和 `（$a$）` 都能正常渲染。

美元符号：

- 不是公式的 `$` 一律写成 `\$`，例如 `\$5`，或改写成“5 美元”。同一行里两个未转义的 `$` 会被当成一个公式。

KaTeX 不是完整的 LaTeX。可以用 `aligned`、`cases`、`pmatrix`、`\tag{1}`、`\mathbb`、`\mathcal`、`\operatorname`。以下写法不要用：

- `\( ... \)` 和 `\[ ... \]`。
- `\usepackage`、`\label`、`\ref`、`\eqref`。
- `tabular`、`tikzpicture`、`\includegraphics`、`\ce`。表格改用 Markdown 表格。

## 脚注

- 引用写 `[^1]`，紧跟在标点之前或之后的文字上，不加空格：“公式由 KaTeX 渲染[^1]。”
- 定义单独成行：`[^1]: 说明文字。`。多段说明的后续段落缩进 4 个空格。定义写在哪里不影响渲染，可以紧跟引用所在段落，也可以集中放在文末。
- 每个引用都必须有对应的定义，不要写没有被引用的定义。
- 不要用 `<sup>1</sup>`、Word 或 PDF 复制出来的上标数字来模拟脚注：它们只是普通文字，不会进入文末的“脚注”区。
- 标签用数字或简短英文，不必手动排序。正文已经用 `[29]` 这类数字引用文献时，脚注标签用 `[^code]` 这样的英文标签，源文件里不会与文献编号混淆（印出的编号仍是自动生成的数字）。
- 脚注适合补充来源或旁注，不要用它放长段正文。

## 结构与其他语法

- 全文只有一个 `#` 标题。之后用 `##`、`###` 逐级往下，不跳级。
- 代码块必须标注语言，单行不超过 100 个字符。流程图和时序图用 ` ```mermaid ` 代码块。
- 提示块只有五种：`> [!NOTE]`、`> [!TIP]`、`> [!IMPORTANT]`、`> [!WARNING]`、`> [!CAUTION]`，类型用大写。其他引用用普通 `>`。
- 表格用标准的竖线语法，每格内容简短。图片用相对路径，并写 alt 文字。
- 需要强制换页时写 `<div class="page-break"></div>`。除此之外，只用 `<details><summary>` 这一种原始 HTML。
- 不要使用 emoji。
- 正文里不要出现字面的 `**`（例如讲 Markdown 语法时），要展示就放进代码里。
